## pvz-web v4.0.160 —— 砸罐子每关地图每局重抽 + 问号罐不再白给植物

用户原话：「问号罐里面基本全是植物，而且每集的地图都是固定的…地图尽量每次都不太一样，不然每次解法都一样，太无味。植物也尽量少一点。」

### 改了什么
- `GameLoop.js` `setupVases()`：关卡模式不再用 `L.n * 7919` 固定种子，改成 `Date.now() ^ random`；
   `chosen` 不再 `sort` 按行列排死；`types` 洗牌从 `if (!L)` 改成无条件；三条内容队列（plants/qs/zombies）加洗牌。
- `VASE_LEVELS` 全表重写：问号罐内容 57% 植物 → 51%；僵尸 12% → 27%；绿罐 44 个（L1~L6 各 3~4，L9/L10 各 6 且全出植物）。
- 新增「行内僵尸血量均衡」块（在 `poolAt` 之前）：算每行僵尸总血，超 avg×1.55 就把一只换到最闲的行。
- 金罐兜底：中间排（col 3~5）一个罐都没有时退到全部罐子。
- 开场横幅「N 只僵尸」→「紫罐 N 个」（问号罐也藏僵尸，报总数剧透、报 L.z 低报）。
- 帮助/关卡面板文案：新增「每局罐位/罐型/顺序重新抽签」「约一半植物 / 四分之一僵尸 / 两成阳光」。

### 关键工程结论（写进 MEMORY.md）
1. **随机化三星标准的前提**：v4.0.150 已把星级改成「损失植物数」，所以布局随机不破坏评价；
   如果哪天星级回到「最少行动点/步数」，随机布局会立刻让标准失效。
2. **随机布局的方差来源不是罐位，而是「行内僵尸血量分布」**。不做均衡时，两只铁桶挤同一行
   = 4 株输出也守不住，机器人每关都有一局输。均衡（换罐位不换内容）后胜率从 75% → 83~100%。
3. **降植物项又不降火力的手法**：把 `p:repeater` 换成 `p:gatlingpea`（1 株机枪 = 2 株双发），
   腾出的名额换成 `'s'`。问号罐植物占比 57% → 51% 靠这一招，火力不变。
4. **可解性底线**：场上植物 : 僵尸数 < 1.2 时机器人稳定崩（L5 8.5:8、L9 12:11、L10 12:12 都试过），
   1.4 以上才稳。末两关的解法是「绿罐给到 6 个全出植物」——植物来源从问号罐挪到绿罐，
   总数不变但玩家观感是「问号罐不再全是植物」。
5. **铁桶 1300 血是硬门槛**：每行只有 1~2 株输出时，铁桶必过。末两关必须给寒冰（减速=等效 dps ×2）
   或机枪/西瓜，光给豌豆没用。
6. `_diag_play.js` 机器人这次修了两个老毛病：① 只数僵尸「只数」不算「硬度」→ 改按 `ZHP` 权重；
   ② `plantAt(row, atkTypes.shift(), …)` 先吃卡再试种。旧版 `_verify_v4150/v4158` 内嵌机器人同病，一并修了。

### 旧验收脚本的断言要跟着规格改（不是代码坏了）
`_verify_v4158` / `_verify_v4150` 里 12 条断言写的是 v4.0.158 的规格（绿罐 4~5、L1 配额 4/8/3、
L10 5/12/9、同关重开必须完全一致、紫罐一律 col≥6、机器人单局必须赢）。这轮全部按新规格改写，
其中「同关重开完全一致」直接反转成「必须不同」。**改规格时先 grep 旧脚本，否则回归永远红着。**

## v4.0.161 双人对战删除「天使/内鬼」死亡变身（用户澄清：当时理解错了）

### 用户原话
「双人对战中植物输掉之后会有一个变成天使或者魔鬼的选项，请把这个功能去掉。我觉得应该是当时的理解错误。
如果有僵尸占领了那一路，那植物就直接输掉了，而不是要过几秒钟才会输掉。」

### 改动
1. `Zombie.update` 的 `x<40` 分支：`_vsZombieReachHouse(this)` → `vsZombieWin()`（当场结算，实测 <160ms）
2. `_checkVsEnd`：删掉 `p2Human / f2 / brainCounts` 三行，破产 2.5s 确认后直接 `vsPlantWin()`
3. 整块删除 `initVsFate / _vsBecome / _vsAngelCapture / _vsAngelSpeed / _vsRage / _vsTriggerDeath /
   _updateVsFate / _vsFateHudRefresh / _vsFateCleanup / _vsOnTraitorDead / _vsFateKeydown / _vsSideHuman`
   + `VsTraitor` 实体类（GameLoop.js 从 342550 字节降到 322409）
4. `InputManager` 4 处「死亡后冻结种植/召唤权」全删（否则 `_vsSideHuman is not a function` 崩溃）
5. HelpGuide 双人对战条目：两条合并成「一局定胜负」，**不要再在文案里提天使/内鬼**（验收脚本 T6e 会红）

### 易踩
- `VsTraitor` 类里 `g.vsFate && g._vsKeys` 是内鬼的移动输入源，类删了要一并删调用；但 `_vsKeys`
  的 keyup 监听原本注册在 `initVsFate()` 内，删掉后双人对战不再需要它
- 双人对战的「撞进屋」判定每帧都会触发（state 仍 WALKING），靠 `vsZombieWin()` 内部
  `state !== 'PLAYING'` 防重复结算，不用加额外锁
- 历史脚本 `_verify_v4102.js / _verify_v4102b.js / _diag_v4102.js / _shot_v4102.js` 专测已删功能，
  已在文件首行加「⚠️ 已废弃（v4.0.161）」标记，**不删文件、下次回归别被它们红着误导**
- 守屋大作战的天使/内鬼是**另一套独立玩法**（`HauntedDorm.js` 的 `playerAngelic/playerTraitor`），
  用户说的「双人对战」不涉及它，不要一起删
