## pvz-web：修复「我是僵尸」三处问题 (v3.7.0 → v3.7.1-izombie-fixes，commit c9d4cb6 已 push)

**用户反馈（一条消息三个问题）**：
1. 有些植物并没有显示出来（空格子）
2. 僵尸只要吃了一路的脑子就好了，我要吃完所有的脑子才能通关
3. 这张我是僵尸的图片上，请让这只僵尸不要跳舞（主菜单第 4 卡插图）

### 问题 1 根因（两个叠加，都是"空格子"）

**(a) type 命名漂移**：僵尸模式敌阵随机池里写了 `potatoMine:` / `fume:`，但 `Plant.getStats` 的分支是
`type === 'potatomine'` / `'fumeshroom'`（**全小写**）→ 匹配不到 → `s.src = undefined` →
`this.element.src = undefined` → 请求 `.../undefined` 404 → 该格无图。
（对照：经典 seeds 的 32 个 type 命名全部正确，所以经典模式无此问题。）

**(b) 敌阵炸弹植物开局自爆**：池里含 cherrybomb / doomshroom / iceshroom，而 Plant.js 有
`this.autoExplode = (cherrybomb|jalapeno|iceshroom|doomshroom|fusion_frostbomb)` —— **种下 1 秒后自动引爆并死亡**
→ 开局 900ms 后敌阵从 30 株掉到 29 株（实测），玩家看到植物凭空消失。
原版 I,Zombie 敌阵本来就没有"种下即炸"的炸弹（只有被动触发型的土豆雷/窝瓜）。

**修复**：
- 池子改名 `potatoMine`→`potatomine`（3 处）、`fume`→`fumeshroom`（1 处池 + 1 处 shooters 列表 + bombTypes）
- 池子移除 cherrybomb / doomshroom / iceshroom（保留 potatomine / squash，陷阱类 ≤3 限制不变）
- `setupZombieEnemies` 落地处防御：`new Plant` 后若 `!plant.element.getAttribute('src')` → 退回 peashooter
- Planter.js 普通分支加守卫 `if (s.src) this.element.src = s.src;`（无素材时不再请求 "undefined"）
- 敌阵植物统一 `plant.autoExplode = false`（兜底：将来往池里加炸弹类也不会自爆）

### 问题 2 修复：吃完全部脑子才通关
原逻辑：Zombie.js `x < 40` → `game.zombieWin(row)` 任一行即通关。
改为：
- 新增 `GameLoop.zombieEatBrain(row, zombie)`：
  - 该行已吃 → 僵尸直接退场（`isDead = true`）不重复计分
  - 吃掉该行：移除该行 🧠 DOM（`zBrainEls[row]`）、`audioManager.play('chomp')`、飘字 `🧠 n/5`、`score += 100`
  - 吃脑僵尸退场：`zombie.isDead = true`（**复用 GameLoop update 末尾的 `isDead → filter + 移除 DOM` 机制**，不自己 splice，避免遍历中改数组）
  - `eaten >= 5` 才 `zombieWin()`；否则 `showAnnouncement('还剩 N 个')`
- `_spawnBrainEls` 初始化 `this._brainEaten = new Array(rows).fill(false)`；`_clearBrainEls` 置 null
- Zombie.js `x < 40` 分支改为 `game.zombieEatBrain(this.row, this)`
- 胜利弹窗文案改为"僵尸吃光了全部 5 个脑子"

### 问题 3 修复：主菜单僵尸不跳舞
`Zombies/Zombie/Zombie.gif`（动画）→ `Zombies/Zombie/0.gif`（**同尺寸 166×144 单帧 PNG，扩展名是 .gif 但内容是 PNG**，
浏览器按内容嗅探正常渲染）→ 视觉零差异、不再播放动画。

## pvz-web v3.8.0 「我是僵尸」平衡重构（commit `bac59e4`，已 push）

**用户反馈原话**："这个困难和地狱还是太难了，我哥哥都快玩哭啦。请在地狱模式里增加一些其他的僵尸。

### B. 敌阵降档（把"机枪射手级"换成"豌豆射手级"，但保留硬骨头）
- 池子移除 `gatlingpea / wintermelon / gloomshroom / fumeshroom / starfruit / hypnoshroom /

   并把冰车瞬移到 `target.x` 正上方（同格仅一株、列距 80px，确保进入 `<40` 判定）。

   防被啃死 + 窗口拉长到 2s + 放宽区间，实测稳定 297.5/2s ≈ 148.7/s（正是设计值）。
4. `page.evaluate` 里操作网页元素后再 `sleep` 检查时，**别用魔法像素偏移**（`+38` 贴边）——
   阈值判定（`< 40`）下 38/40 这类边界值会让结果随帧漂移；直接用 `x` 对齐最稳。
5. 排查偶发失败的正解：写"连续 N 次"的 debug 脚本（如 /tmp/dbg_crush2.js 跑 12 轮并打印
   每轮 setup + 失败现场），一次就定位到 `zstate: DYING`。

## tank-battle v1.4.2 — 结算锐评排版修复（fix）
提交 `47fdbdb`，已 push origin main。用户反馈"MVP 结算页的锐评太长，字跑到屏幕外"。

### 问题根因
`drawMVP()` 里锐评是**单行居中直出**：`ctx.fillText(\`P1 锐评: "..."\`, cx=416, quoteY=720)`，

### 修法（双保险：绘制端折行 + 文案端缩短）

**绘制端 game.js（真正的兜底）**
- `_wrapText(ctx, text, maxWidth, maxLines)`：CJK 逐字断行（不需要词边界），
  超出 maxLines 时末行截断 + 去尾部标点 + `…`
- `_fitQuoteLines(ctx, raw, maxWidth, maxLines, baseSize=22)`：字号阶梯

  多行排布。关键是把 rows 展平成一维数组（含 spacer），
  `qy = bottomBaseline - totalH + lh` 起画，保证**最后一行基线恒为
  `CANVAS_SIZE - 32`**。左右安全边距 `quoteMaxW = CANVAS_SIZE - 96`
- 单人（players[1] 不存在）/双人/平局三种分支都走同一套

**文案端 mvp.js**
- `MAX_QUOTE_LEN = 28` + `composeQuote(p,b,suf)` 逐级降级：
  完整三段 → 去前缀(`b，suf`) → 只留(`p+b`) → 硬截断加 …

## pvz-web v3.9.1 修复「画面整体右下偏移一格」（commit `b6e43d5`，已 push）

**用户反馈**：\"游戏玩着玩着，突然画面发生了偏移。就是所有的植物都往右下方移动了一格，
也就是往右边移动一格，往下又移动了一格。最下面的植物都移到屏幕外面去了。\"

### 定位过程（截图取证 → 反推机制，值得复用）
1. 先读截图元数据：1820×1320 是 **DPR=1 的窗口**（不是 2x retina），页面 viewport ≈ 1820×1212，
   `scale = min(1820/900, 1212/600) = 2.02` → 容器左上角 ≈ (1,108)。
   **校验**：紫色蘑菇（小喷菇）帽心相邻间距实测 = 161.7 / 202 设备px → ÷2.02 = **80 / 100 游戏px**
   正好等于 `cellWidth/cellHeight` → 反解出的 scale 可信（这一步是整个推理的地基）。
2. 用 PIL 连通域抠出 20 个蘑菇帽的精确中心 → 换算回容器坐标 → 与「格心 = offsetX+col*80+40」比对，
   得到**统一残差**。再按各 sprite 自身的"帽心相对画布中心的偏移"修正（PuffShroom.gif 40×66，
   帽心 (-2.5, +9)），残差收敛到 **(+20, +33)**（小喷菇）与 **(+48, +48)**（西瓜投手 96×96）。
3. 关键识别：**不同贴图的偏移量不同，且恰好各自等于"该贴图尺寸的一半"** → 这不是"整体平移 N 像素"，
   而是**元素失去了"中心对齐"基准、退化成左上角对齐**。
4. 全仓搜 `\.style\.transform` → 命中 `EventManager` 的「💪 兴奋剂」：
   `p.element.style.transform = 'scale(1.2)'` —— 直接赋值把 CSS `.entity{transform:translate(-50%,-50%)}` 整段覆盖。

### 根因（一条 CSS + 一次内联赋值）
`.entity` 的**中心对齐**完全依赖 CSS 的 `translate(-50%,-50%)`；任何 `element.style.transform = '...'`
都会把它覆盖掉 → 元素按**左上角**对齐 → 视觉上整体**右下偏移半个贴图**（偏移量 = 贴图尺寸/2，与缩放倍数无关）。
- 西瓜投手 96×96 → 右下各偏 48px（≈ 一格，最显眼）→ 玩家说的"移动了一格"
- 小喷菇 40×66 → 偏 20×33px
- 第 5 行再往下偏 33~48px 就被顶出 600px 高的容器 → 玩家说的"最下面的植物都移到屏幕外面去了"
- 事件不重置 transform → 偏移**永久保留** → 玩家说的"玩着玩着突然偏移"（而不是"一直偏"）

### 修复
1. `Entity` 新增统一入口：`setTransform(extra)`（幂等，恒定 `translate(-50%,-50%) [extra]`）
   与 `addTransform(extra)`（可叠加，空串时先补 translate；已有自定义基准则原样追加不擅改）。
2. 改掉全部同类写法：
   - 「💪 兴奋剂」`= 'scale(1.2)'` → `p.setTransform('scale(1.2)')` ★主犯
   - 「🐜 缩小 / 🦖 巨化」`+= ' scale(...)'` → `addTransform(...)`（原来 `+=` 在空串上会拼出**裸 scale**）
   - 「💃 尬舞」`transform='rotate(1080deg)'` → `setTransform('rotate(1080deg)')`，
     并把 3 秒后的还原从"粗暴清空"改为**原样还原事件前的 transform**（否则会连带抹掉缩小/巨化）
   - 混合向日葵小阳光 `scale(0.6)`、融合植物自定义图 `scale(1.2)` 同样改走 helper
3. 纯可视化修复，**未改任何数值/玩法**。
