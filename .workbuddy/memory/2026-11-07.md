## v4.0.152 三个新泡泡玩法上线（提交 73cf3ab，已 push）

用户要求：先造方案 A 放进小游戏 —— 删「植物消消乐」换 A、换「豌豆射击场」为 B、删「植物贪吃蛇」换 C。
最终小游戏总数仍是 10 个。

### 架构：抽出 `BubLane` 内核（关键决定）
六边形泡泡场地的一整套东西抽成可复用类，三个玩法只写规则层：
```
new BubLane({ R, COLS, LEFT, TOP, rows, sx, sy, deadline, nColors,
              fillRows, gapEvery, ceilRows, missPush, missLimit })
```
方法：`aimLimit() / aimAt() / nudge() / fire() / advance() / update() / land() /
findCell() / cluster() / settle() / removeCells() / clearTombsNear() /
dropFloating() / pushCeil() / burst() / wipeColor() / wipeRow() / colorNear() /
draw() / drawAim() / bub() / tomb() / spBall()`。
钩子：`onLand(lane,res) / onClear / onDead / onSpecial / pickNext`。
**意义**：三份网格逻辑如果各写一遍必然走偏（v4.0.151 的幽灵球就是单份里踩的坑），
共用内核后判负、下压、掉落只可能错一次。

### 三个玩法
- **A 机械龙攻城** `DragonRaid`：`noClear=true`（清空场地不算赢）。龙 640 血，
  消 1 颗 = 尖刺 +4 伤害；70%/35% 两道血线推阶段（2 阶段丢护甲、喷吐 6.6→5.0s 并丢墓碑；
  3 阶段眼睛泛红、4.0s 一次、两块墓碑）。`TOMB=99` 不可同色消，只能被贴着它的爆破带走。
- **B 泡泡对轰** `BubbleDuel`：左右两块 9 列场地。消 4/6/8 颗 → 给对面顶行塞 1/2/3 块墓碑，
  悬空掉落 ≥5 再 +1。开局 AI 代打右侧（1.55~2.45s 一发），按方向键立即接管。
- **C 泡泡塔** `BubbleTower`：8 层，`loadFloor(n)` 每层重铺；第 2/4/6 层解锁
  炸弹球 `burst(R*2.15)` / 彩虹球 `wipeColor` / 闪电球 `wipeRow`，概率 10%→22%。
  连击 ≥3 有倍率。

   教训：**按段落切片时先确认这段里有没有属于下一节的常量**；改完立刻 `node --check` + 打开全部 10 个玩法。
3. **机器人 16 发就死**（不是平衡问题，是测试脚本问题）：机器人挑「剩余空间最多」的格子，

6. **居中飘字必然压东西**：泡泡塔炮台在正中央（x=450），任何 `center` 对齐的

## v4.0.154 守屋大作战：僵尸阵营杀光幸存者却不结算（提交 3c36719，已 push）

用户：**僵尸阵营已经把 6 名幸存者全部击杀，依旧没有获胜。**

### 根因：判胜挂在了「某几条击杀路径」上，而不是「场上状态」上
`_checkPlayerDown()` 是「幸存者（人机/P2）掉到 0 血」的**唯一统一出口**，所有伤害来源都汇到这里。
它的人机分支原本只有两条：
- `playerAngelic && ais.every(dead)` → 判负
- `_anyTraitor() && plantSideAlive()===0` → 判胜（内鬼）

**唯独没有 `isZombieFaction`。** 于是：
- 玩家自己张嘴啃死最后一人 → 走 `_tick` 里 6700+ 的「啃咬分支」，那条**自带** `if (_plantSideAlive()===0) gameOver(true)` → 以前能赢，所以这个 bug 一直没暴露；
- 己方僵尸 / 号令尸潮的小鬼靠**接触伤害**（`_tick` 里 `for (p of allPlayers) p.hp -= touchDps*dt` → `_checkPlayerDown(p)`）蹭死最后一人 → 只走 `_checkPlayerDown`，**没有任何判胜** → `plantSideAlive()=0`、HUD「幸存者 0」，但永远不弹结算。

### 修复（三层）
1. `_checkPlayerDown` 的判胜条件：`_anyTraitor() || isZombieFaction`，文案按阵营分（「猎杀完成」/「内鬼得逞」）。
2. **`_tick` 里 0.5s 一次的终局兜底巡检**：只看「场上还有没有植物方活人」，不关心谁杀的。
   → 这才是根治：以后再加任何伤害来源都不会再漏。
3. 顺带修三处同源问题：
   - AI 死亡统一记 `kills`（挪进 `_checkPlayerDown`），原来只有亲手咬死才 +1，小怪咬死的 HUD 一直是旧值；
   - 天使分支 `ais.every(dead)` → `_plantSideAlive() <= 1`（只数人机，2p 里 P2 还活着也会误判负）；
   - `_becomeAngel` 里 `_plantSideAlive() === 0` **恒不成立**（天使自己 isZombie=false，会 +1）→ 这段兜底从来没生效过，改成 `<= 1`。

### 顺手补的坑：判胜不能抢跑
2p 里 P2 倒下会 `pendingFate=true` 等玩家按 N/M（天使/内鬼）。此时 P2 的 `dead=true` 不算植物方，
`plantSideAlive()` 可能已经是 0 → 新加的两处判胜会**在玩家还没按键时就把游戏判成内鬼胜利**。
→ 所有「邪恶方判胜」统一加 `!_humansAll().some(h => h.pendingFate)`。

### 教训（可复用到所有多结局游戏）
- **别把「谁赢了」写在每条击杀链路里**。链路会越加越多（啃咬 / 接触伤害 / 盲盒事件 / 尸潮小怪 / 推车），
  每加一条就要记得补一次判定，漏一次就是「杀光了但没结算」这种最难查的 bug（用户看到的是"没反应"，不是报错）。
  正确做法：**伤害只管改状态，胜负由一个定时巡检按场上状态统一裁决。**
- 排查顺序：先看「死亡出口函数」有几条分支 → 再看「谁调用了它」→ 对比不同阵营能走到哪条分支。
  本次最快的定位方式是写一个直接调 `_checkPlayerDown` 杀光全场的小脚本，看 `over` 是否变 true（僵尸阵营 false / 内鬼 true 一眼就分出来了）。
