## v4.0.105（4b3fe61）守屋人机「钉床」
- 用户实报：2p 守屋里人机「一进入房间、碰一下阳光菇就直接出来了」，要求直接固定在阳光菇上、就地种植
- **根因（真正的一击）**：`_tick` 里 AI 抵达床位的认领判定只查 `owners.length < capacity`——对「自己已认领的房」恒为假
  （capacity=1、owners=[自己] → 1<1 失败）→ 人机回自己家（v4.0.80 抢盲盒回来 / 逃亡回来）走到床边被判「这房有人」→
  立刻换房跑路（else 分支重新找房）→ 进屋碰床又出来的乒乓循环，永远住不下；且每次换房都往新房间 owners 里塞自己
- 修法：①目标房 `owners.includes(ai)` → 直接归位（不再换房）；②新增 `_pinToBed(p, rm)` 钉床——入住即坐标对齐到
  `beds[0]` 格中心（阳光菇所在格）+ 清路点；③`_tick` 移动循环里加钉床短路（pinned && room && !fleeing && !targetDrop → 原地 + continue）；
  ④真人手动不钉（`_claimRoom` 只钉 `p.isAi || p._afkHost`），解钉：贴脸逃亡/门破弃房/归还控制权/换房分支
- 顺带修：门破逃亡 `Math.random() < 0.05` 是**每帧**概率（60fps≈3 次/秒）→ 门一破人机瞬间弃房丢阵地；改成 `ai.doorBrokenT` 累计 0.8s 再评估 5%
- 测试：`_verify_v4105.js` 13/13（回自家床不换房/进空房认领即钉床/12s 零位移且植物 1→3/门破门闸 0.35s 不弃房 2.2s 弃房/托管钉床+归还解钉）
  + `_verify_v4105b.js` 7/7（1p 5/5 入住钉床、2p 60s 零离房）
- 教训：①**采样/断言先量时间轴**——T1 走回床要 2.7s，我 3.5s 断言差点误判为失败；用轮询到达代替固定 sleep
  ②测试里断言引用不存在的字段（`t1r.rmIdx` 只在 setup 返回过）= 静默 false，务必核对字段来源
  ③诊断顺序：path setter 陷阱（抓赋路径调用栈）在 headless 下 75s 零命中 → 说明 headless 静态站位复现不了，得靠代码推理 + 直接构造场景

- **核心教训 1（本轮最大发现）：只调血量曲线没用，必须和「出怪量 + 屏幕人数」一起调。** 稳态关系 `场上人数 A = 出怪率 × 存活时间 L`，且 `出怪率 ≈ 击杀率 = 总吞吐 / 单只血量`。只把血量拉高 → 击杀率暴跌 → 出怪闸门（`spawnBatch`/`spawnTick`）顶死 → 画面还是空的
- **核心教训 2：真实吞吐 ≈ `dpsOf` 的 25 倍**（穿透/多重让一发子弹打多个）。按 `dpsOf` 估血量会低估两个数量级，必须用「实测击杀数 × 当时单只血量」反推
- **核心教训 3：出生线必须在 HUD 之下。** 原来 `y = -28 - rand(0,96)`，HUD 面板+横幅盖住画布上部约 300px → 敌人 0.9 秒寿命全躲在界面背后，看起来"整屏空着"。改成 `TUNE.spawnY=140 + rand(0,90)` 后立刻满屏
- **核心教训 4：城墙必须够厚，否则"怪压下来"和"4 分钟结束"不可兼得。** 200 血时只要几只怪摸到墙就秒破（97~113s 就 OVER）；`wallBase` 200 → 2800 后才有真正的围攻过程；酸雨伤害改为按 `G.wall.max/200` 等比缩放，E1 用例同步关刷怪（`TUNE.popBase=-9999`）
- **新验收指标：敌人纵深（存活敌人 y 的中位数/90 分位）。** 光看"场上几只"会骗人（可以全堆在出生线上）。目标：中位 y 落在 180~480 的可见区，而不是 -80
- 血量曲线形状 `hpA*(1+t/hpT)^hpE`（hpA 1.0 / hpT 10 / hpE 2.1）+ **中期钟形加厚** `1 + hpBell*exp(-((t-hpBellT)/hpBellW)^2)`（hpBell 2.0 / 110 / 70）——成型那段火力最猛，不加厚就整段空屏
