
## tetris-battle v1.1.3（重大消行 bug）
- 用户反馈"3 排可收只收了 2 排，满行不消" → 两个叠加 bug：
  1) **主因**：finishClear 用 splice(行号)+unshift 逐行删，unshift 把未删满行推后一格，后续按旧行号 splice 删错行 → **多行消除必少删一行**（降序排序也救不了，因为 unshift 是往下推）。修复：`filter` 一次性剔除满行再 unshift 补空行
  2) 消行动画 220ms 内垃圾落地/清底会推移棋盘，lock() 记录的 pendingClear 行号失效 → finishClear 改为**删行前重新扫描满行**（顺带：动画期间新凑满的行也会被收掉）
- 教训：**"边删边补"的数组操作必须整体重算，绝不能边 splice 边 unshift 还拿原始索引**；回放类测试要断言"棋盘上不再有满行"而不只是 lines 计数
- /tmp/tetris_verify.js 会被系统清理，本次整体重建（20 项断言）；node 路径已变为 22.22.2-3
- commit 20eb0f1 + push

## tetris-battle v1.1.4（软降按块生效）
- 用户反馈：按住下键不放，前后的方块全都接连狂掉难控制 → 根因：softDropping 是按住状态，spawn() 生成新块时没清，加速状态跨块继承
- 修复：spawn() 里强制 `this.softDropping = false`——软降只对当前块生效，新块必须松开再按一次下键才加速（不能靠"松开检测"：按住到底再松开的时序玩家自己难控制，块出生即清状态最干净）
- 与 DAS 区分：左右连移（v1.1.1）是持续按住连续横移，属正常手感保留；软降是节奏型操作，按块隔离才可控
- 测试：hardDrop 后断言新块 softDropping=false；21 项全过；commit 269648c + push
- 经验：**"按住生效"类状态机凡是跨实体/跨回合的（如跨方块），新实体出生时必须显式重置**，与 e.repeat 无关
