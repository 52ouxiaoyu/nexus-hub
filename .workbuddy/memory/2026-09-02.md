# 2026-09-02

## PVZ 炸弹融合机制重构（v3.2.31-bombhost → v3.2.32-bombauto, commit 137203a）
用户反馈上一版"炸弹母体+点击引爆+手套多次合成"太繁琐。新机制（用户原话：种下直接引爆、先执行本来功能、爆炸后 3×3 范围内自动融合）：
- **恢复原版自动爆炸**：樱桃/辣椒/寒冰菇/毁灭菇种下 ~1s 自动引爆，无需点击/手套；点击仍可立即引爆(explodeNow)。
- **爆炸自动融合**：引爆瞬间扫描自身 3×3（含对角，同寒冰菇范围）内所有可配方植物，逐个在原植物格生成融合产物（豌豆→樱桃射手、寒冰菇+西瓜→冰西瓜、毁灭菇+向日葵→毁灭向日葵、辣椒+坚果→火炬树桩、寒冰菇+豌豆→寒冰射手…）；炸弹为催化剂随爆炸消耗。
- 融合仅 fusionMode（经典冒险模式不触发）；种炸弹在已有植物上=同格立即融合（仅融合模式）。
- **修复**：fusion_cherrybomb_peashooter 此前 1s 后会自动爆炸消失（isBombHost 守卫误伤），现改为常驻射手、阵亡时才爆；用 `autoExplode` 标记取代 isBombHost（仅 4 基础炸弹 + fusion_frostbomb 自动爆）。
- 移除手套炸弹母体分支与 InputManager 点击引爆的 isBombHost 依赖。
- 验证：`_verify_bomb_auto.js`（puppeteer, executablePath=/Applications/Google Chrome.app/...；新版 puppeteer 无 waitForTimeout 需 setTimeout 替代）12/12 通过。
- 改动文件：Plant.js(autoExplode 定义/branch 条件/explodeNow)、GameLoop.js(删手套母体分支、tryPlanting 加 fusionMode 门)、InputManager.js(点击引爆改 autoExplode)、version.json feature 更新。

## PVZ 爆炸植物统一流程（v3.2.33-bombslot, commit 398ff0d）
用户实测反馈"只有种到植物同一格才融合、而且没有爆炸；旁边空格只炸僵尸不融合"→ 怀疑多因浏览器缓存旧版（同格静默替换是旧行为特征），同时同格路径确实跳过了爆炸。
- **统一语义**：无论炸弹种空地还是种到已有植物身上，一律"先执行原版爆炸 → 再以自己为中心融合 3×3"，全程无需手套。
- **同格种植改造**（GameLoop.js tryPlanting）：种到已有植物上不再瞬间静默替换 → 计算目标植物 3×3 内最近的空格作为炸弹落点（走标准种植→自动引爆→3×3 融合含目标）；仅当 3×3 全被占满才兜底同格立即融合；无配方组合不扣阳光并提示"可种在旁边空格"。
- 验证：新增 `_verify_samecell.js` 8/8（同格樱桃/寒冰菇先炸后融、旁边空格回归、经典模式不融、无配方退款、满格兜底）+ `_verify_bomb_auto.js` 12/12 回归通过。
- 版本 v3.2.33-bombslot，asset 1788355723，已推送 origin main。
- 经验：炸弹机制排查时先用真实 UI 路径(点 btn-fusion→选种→tryPlanting→rAF 真实 dt)复现，勿只信引擎级 step 测试；puppeteer 中 state 必须为 PLAYING 才会跑更新循环。
