## v1.0.4 袋口 WPA/BCA 标准化（用户报"角袋边袋是直角"）

用户报：袋口设计潦草，角带/边带都是直角边，没有斜边。
查 WPA/BCA Equipment Specifications：
- **角袋 mouth 4.5"-4.625" ≈ 11.5cm，两侧 cushion 端面外夹角 142°**
  → 每边向桌外张 26°（顶端相对底端水平偏移 dx = ch·tan(26°) ≈ 0.022m）
- **中袋 mouth 5"-5.125" ≈ 12.7cm，两侧 cushion 端面外夹角 103°**
  → 每边向袋口中央倾 38.5°（偏移 sIn = ch·tan(38.5°) ≈ 0.036m）
- 角袋比中袋**窄 1.27cm**（WPA: side pocket 0.5" wider than corner）
- 物理 pocket capture 半径（0.108m / 0.088m）保持不变 → 手感不变

实现：
- 用 BufferGeometry 自定义 4 顶点斜面薄片（slopeQuad）覆盖 cushion 末端
- 角袋：每角 2 块斜板（短边 + 长边 cushion 端面），向桌外斜 26°
- 中袋：每袋 2 块斜板（左右 cushion 端面），向袋口中央斜 38.5°
- 视觉增强：tiltScale=1.6× 让斜面在远景也明显（dx≈0.035m, sIn≈0.060m）
- cushion 主体 box 缩短到桌面边缘（不再突出桌外 ct），
  斜板完全替代 cushion 末端"鼻尖张开"部分

### 关键坑
**cushion 端面斜板方向一开始写反了**：中袋两侧斜板顶端都写成了
"-sideGap - sIn"（向桌外），结果两 cushion 顶端在袋口中央几乎相撞，
袋口被堵。修正后顶端用 "-sideGap + sIn"（向袋口中央倾），中袋两
cushion 顶端在袋口中央"鼻尖对鼻尖"，mouth = 2×sideGap = 0.126m。

**WPA "external 142°" 几何含义**：从袋口外侧看 cushion 端面之间夹角
142°（即"more open than 90°"），意味着 cushion 端面向桌外张 26°，
顶端比底端更靠桌外。这跟直觉相反（"外角 142°"听起来像 cushion 端面
向桌内收），要查 AzBilliards 论坛 Andrew 的图示才能确认。

## tank-battle v1.4.3 — 大本营装甲顶棚（feat）
提交 `5046443`，已 push origin main。用户诉求："大本营正上方，不管哪个位置，都布置几块坚硬石头，
防止牛逼一点的敌人刚出来往下打几炮就把大本营打没。"

### 先搞清"基地到底怎么被打掉的"（关键，别想当然）
地图常量：`TILE_SIZE=32, GRID_SIZE=26`，基地固定 `grid[24][12]=grid[24][13]=grid[25][12]=grid[25][13]=BASE`，
即 **row24~25 / col12~13**；`setBaseWalls(BRICK)` 在 row21~25 / col10~15 砌一圈砖；`baseHealth=5`。

**子弹打墙的规则（本次最大发现）**：
`Bullet.update()` 只对「子弹中心所在的那一个 tile」做判定（`Math.floor((x+size/2)/TILE_SIZE)`），
命中 BRICK/STEEL/UNBREAKABLE/BASE 后即 `active=false`。其中：
- 命中 BRICK/STEEL/UNBREAKABLE → 走 `triggerExplosion()`，而
  `if (small || this.type !== 'EXPLOSIVE') return;`
  → **普通子弹(NORMAL/MISSILE/SPREAD/BOUNCE)完全打不穿砖！** 只有
  `piercing`(LASER) 和 `EXPLOSIVE` 的 AOE 能拆砖。`Tank.shoot()` 用 `this.weaponClass` 决定弹种。
- 敌人能拿到爆炸弹的路径：**`HEAVY` 变体有 30% 概率 `weaponClass='EXPLOSIVE'`**（stage>2 出现），
  以及 BOMBER / MIMIC BOSS。HEAVY 就是"牛逼一点的敌人"。
- 敌人出生点：`sx = [2,12,22]*TILE_SIZE`，即 **1/3 概率正好出生在 col12 —— 基地正上方那一列**！
  EXPLOSIVE 一发 radius 1.5~2.5 能把 row21~23 的砖整片掀掉，随后几发直射基地。
  → **A/B 实测：无护盾时 14 发高爆弹就把 baseHealth 5 打到 0**（基地瓦片全变 10=BASE_DESTROYED）。
- 另外 `Boss` 有个"卡住就拆墙"逻辑（`Boss.update`里 `Boss Demolition`），但守卫是
  `if (!(tx>=10 && tx<=15 && ty>=22))` → **row21 那排砖是露在外面的**，大 BOSS 卡住时会啃掉它。

### 修法（`GameMap.setBaseShield()`，每张地图强制生成）
```
row20, col11~14  →  STEEL          // 装甲顶棚
row19, col12~13  →  UNBREAKABLE    // 护心石（唯一能竖直直射基地的两列）
```
- **调用位置是坑**：必须放在 `guaranteeConnectivity()` **之后**。因为
  `forcePath()` 会把 `impassable`（含 UNBREAKABLE）改成 EMPTY 来凿路，keyPoint 里
  正好有 `[12,20]`（"base top"），路径会走 (12,19) → 把护心石挖掉。
- 顺手把 forcePath 的保护区抽成 `inBaseProtectedZone(x,y)` =
  `x ∈ [BASE_SHIELD_X1-1, BASE_SHIELD_X2+1] && y >= BASE_PROTECT_Y(18)`，
  **上沿从 row20 提到 row18**，避免通路在大本营护盾上掏洞（原写法是硬编码
  `x>=10 && x<=15 && y>=20`，4 处 `!()` 取反 + 1 处 `continue`，共 5 处）。
- 平衡：侧面砖墙 (24,10/11/14/15) 仍可破 → 敌人必须**绕到两侧**才能威胁大本营，
  游戏仍能输（实测侧面高爆弹 5→0）。没有变成无敌。

### 验证方法论（可复用）
1. **A/B 对照是说服力最强的写法**：在页面里 monkey-patch 原型方法
   `const orig = Object.getPrototypeOf(g.map).setBaseShield; proto.setBaseShield = function(){}; g.map.reset(lv); proto.setBaseShield = orig;`
   → 同一套围攻脚本跑"修复前/修复后"两遍，直接对比 baseHealth 与基地瓦片。
2. **造弹别调 `enemy.shoot()`**（有 cooldown、依赖方向）。直接
   `g.bullets.push(new Bullet(g, enemy, col*32+16-size/2, 3*32, 'DOWN', 3, 'EXPLOSIVE'))`
   + 自己步进 `for (const b of g.bullets) if (b.active) b.update(); g.bullets = g.bullets.filter(b=>b.active)`
   （EXPLOSIVE 的 `size=12`，要按 size/2 减半对齐 tile 中心）。**每发之间要 step 够帧数**
   （speed 5~6，18 格 = 576px ≈ 100+ 帧），否则前一发还没走完就发下一发，结论失真。
3. **连通性断言别只挑一个点**：`isConnected(x1,y1,x2,y2)` 里终点也必须是被 BFS 推入的
   可通行格，若终点本身压着随机钢块就直接 false（假失败）。改成"候选点集合里任意一个可达"。
4. 截图前 `g.update = function(){}` 冻结，且 **不要设 `gameState='PAUSED'`**（会画出全黑暂停帧）；
   设 `'PLAYING'` 顺手 `g.spawnTimer=999999; g.enemies=[]; g.bullets=[]` 画面最干净。
   用 `elementHandle.screenshot({clip})` + `box.width/832` 缩放系数可以精确裁到基地那一格。

## v1.0.5 台球库边/袋口整体重做（修 v1.0.4 事故）

### ① Boss 掉落收敛

### ② 掉落公平化：`Game.fairDropSpot(preferX)`（本次最重要的实现）
调用点：`Tank.destroy` 里 `this instanceof Enemy && !this.isBoss` 的掉落分支，
把 `new PowerUp(this.game, this.x, this.y, type)` 改成 `const spot = this.game.fairDropSpot(this.x + this.width/2)`。
算法三步：
1. **先按分界线均匀采一个目标点**（这是分布对称的关键——不要"采样后重试直到落空地"，
   那样会因为下半场砖多而系统性偏向上方：实测均值会掉到 384 而不是 416）；
   `ty = FRONT_LINE_Y - 32 ± 4格随机`，并 `Math.round(v/32)*32` **对齐网格**。
2. 从目标点向外按 `DROP_SEARCH_OFFSETS`（整格步进 ±2 格、按距离升序）找**最近可落点**：
   先要求整块 64×64 在空地，退而求其次只要中心 32×32 干净。
3. 兜底沿分界线由近到远逐格扫描（地图必有通路）。
**对齐网格是决定性因素**：`GameMap.isBlocked(x,y,64,64)` 是按"盒子覆盖到的整格"判定的，
64×64 的道具骑在格子边界上会被算成压住 **3×3** 格，对齐后只压 **2×2** 格。
实测"能整块落在空地"的比例 **72% → 100%**（横向 3 格 vs 2 格的差别就这么大）。
实测 100 次真实掉落：y 均值 416、范围 ±5 格、上下两侧各占 25%+、无一贴敌方出生点、无一埋进墙/水。

### ③ 敌方表情包
- `EMOTE_POOLS` 五类共 27 个 emoji：idle / angry / happy / scared / hurt
- 挂在 `Enemy` 上的状态：`emote / emoteTimer / emoteMax / emoteKey / emoteBag / emoteCooldown / emoteEventLock`
  + 方法 `_pickEmote(key)`（抽签袋）、`emoteReact(key, event=true, duration)`、`_updateEmote()`

  `Tank.destroy` 掉血未死→angry/hurt、玩家被敌人打死→killer.happy、`PowerUp.applyEffect` 敌方抢到→happy

### ⚠️ 本次最大的坑：`_drawEmote` 里 `this._roundRectPath` 不存在
`_roundRectPath` 是 **Game** 上的方法，`_drawEmote` 挂在 **Tank** 上 → `this._roundRectPath` 是 undefined，
**每次绘制都抛异常**，而 `Game.draw` 里是 `this.enemies.forEach(e => { try { e.draw(ctx) } catch(e) {} })`
—— **异常被完全静默吞掉**，坦克照常显示、只是没有气泡，肉眼极难发现。
（我一度把白色道具盒 / 残骸图标误认成"表情气泡已经画出来了"。）
正确写法 `this.game._roundRectPath(...)`。
**通用教训：给实体类新增"用到 Game 工具方法"的绘制逻辑时，一定检查方法到底挂在哪个类上；
并且验证脚本必须加"渲染真出像素"的断言**，例如
`getImageData` 扫坦克上方区域统计亮像素（本次实测 803 个），光断言"没抛异常"是不够的。

### 可复用的验证套路（本次新踩出来的）
- **顶层 class 在浏览器里的取法**：`class Foo {}` 声明在全局词法环境（不在 window 上），
  但 `window.eval('typeof Foo !== "undefined" ? Foo : null')` **能拿到**（间接 eval 跑在全局环境）。
  比 `g.enemies[0].constructor` 可靠得多（拿不到 Boss）。
- **调实例方法做隔离渲染**：`const fake = Object.create(Tank.prototype); Object.assign(fake, {...});`
  → `Tank.prototype._drawEmote.call(fake, ctx)`，比在实机上截图稳得多（实机有 shake/残骸/在途 setTimeout 干扰）。
- **截图前清场不要只清一次**：`startGame()` 之后仍有 `setTimeout` 在途（刷怪、连爆），
  正确做法 = `g.update = function(){}` 冻结后，用 `setInterval(..., 25)` 反复清 transient 数组
  （并把 `g.enemies` 重置成自己造的那批），截图前再 `clearInterval`。
- **掉落地图示意图**：直接在页面里建 `<canvas>`，按 `map.grid` 填色 + 画分界虚线，
  再叠 260 个真实 `fairDropSpot()` 采样点 → `toDataURL()` 取回来写盘。
