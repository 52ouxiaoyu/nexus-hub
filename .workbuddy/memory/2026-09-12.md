## billiards v1.0.6 · 袋口朝桌面敞开（不再是封闭的完整圆）

用户反馈：每个球洞都是完整圆形，看着"四周都是边、球打不进去"，
要求把面向球桌那一侧的圆边去掉、露出能让球进去的开口。

### 改法
- 洞口轮廓 = 外侧圆弧（被木框包裹）+ 朝桌内张开的两条外张直边（喇叭口）并伸进台呢
  → 形状本身不再是完整圆
- 朝桌内用**顶点透明度渐隐**（`setAttribute('color', itemSize 4)` +
  `material.vertexColors / transparent`），淡出深度随横向偏移收窄 → 渐隐区呈扇形张开；
  圆靠桌内那段弧彻底淡到 0，黑色与台面连成一片。朝木框一侧保持不透明黑
- 镶边（rim）只沿外侧圆弧；袋口内壁圆筒改成**部分圆筒**
  （`CylinderGeometry(..., true, thetaStart, thetaLength)`）只包朝外部分
- 中袋：库边端面斜切让出的两个小三角 + 木框挖洞（内边界角落 √(sideGap²+cw²)=8.4cm）
  大于洞口半径 7.8cm → 漏背景，补两片深色衬片（只填两侧，不跨越洞口中心）
- 贴图渐变：黑心占到大半、只在最外圈淡化（朝内边界已交给顶点 alpha 处理）

### 两个几何坑（重要）
1. **轮廓绝对坐标 + mesh.position 双重偏移**：`pocketOutline()` 生成的点已含圆心偏移，
   我又写了 `mesh.position.set(cx, …)` → 洞口被推到桌外，**整块不可见**；
   屏幕上看到的其实是"木框挖洞后露出的背景"（灰蓝）。
2. **绕向翻转 → 背面剔除**：轮廓在 xz 平面按角度递增生成，转成 shape 用的 `(x, -z)`
   后绕向翻转 → ShapeGeometry 法线朝下，单面渲染被剔除 → 同样表现为"洞口不见了 + 露背景"。
   改 `side: THREE.DoubleSide`。

### 诊断方法（可复用）
POOL 暴露 `get scene()`；在 puppeteer 里把 `scene.background` 设成洋红 +
`traverse` 把所有 `geometry.type === 'ShapeGeometry'` 的 mesh 材质换成纯绿 ——
**"换成纯色却满屏没变色" 就说明这些 mesh 根本没进渲染**，比盲猜材质/光照快得多。

### 验证
- 八球规则回归 12/12 全过（物理一行没动）
- 三视角截图零报错；另写脚本扫全桌面找"蓝>绿>红"的背景色像素 → 只剩蓝球与边缘抗锯齿误报

## billiards v1.0.7 · 开球规则修正 + 关键提示不再被顶掉

用户问："开球打进一个球之后，为啥颜色还不能定下来，直接换成对家打了？"

### 先查规则（WPA 3.3 / 3.4）——花色未定是**官方规则，不是 bug**
- 3.3(c) 开球进球且未犯规 → 开球方继续，台面保持 open
- 3.3(d) 开球无球落袋 → 换对手（需 4 颗碰库才算合法开球）
- 3.4 花色要等**开球之后**的第一次合法进球才定；开球进全色+花色也不定
- "进球即定花色"是 APA / 街机规则（take what you make）
→ 已用 AskUserQuestion 与用户确认：**保持官方标准**

### 但确实查出 3 个 bug（用户"换成对家"的描述对上了）
1. **开球未进球也续杆**：`if (wasBreak) cont = true` 无差别放行 → 实测开球空杆还能接着打。
   改 `cont = pottedNon8.length > 0 || eightSpotted`。
2. **犯规原因被瞬间覆盖**（最可能就是用户遇到的）：
   `showMsg('犯规：…')` 紧跟 `switchPlayer()` 里的 `showMsg('轮到 xxx')` → 原因全丢。
   实测 **10 次开球有 3 次母球跟着落袋**，其中一次"进 2 球 + 母球落袋"→ 与用户描述完全吻合。
   改 `switchPlayer(quiet)` 静默换人 + 把原因与后果合成一条。
3. **同类**："分到花色"提示被"好球！继续击打"顶掉 → 玩家看不到自己拿了哪组。
   改 `infoMsg` 优先级最高。

### 可理解性补齐（不改规则，只让规则可见）
- HUD："花色未定" → **"台面开放 · 花色未定"** + 琥珀色高亮（`.p-group.open`）

## billiards 袋口尺寸核实（只核实 + 出预览，未改正式代码）

用户问："6 个球洞跟真实台球是不是不一致？我看过去中袋明显比 4 个底袋大一点，不知道哪个 OK。"

### 核实结论（WPA 官方规格 vs 实测）
- WPA：**角袋 mouth 11.43~11.75cm**；**中袋 mouth 12.70~13.02cm**（中袋本来就比角袋宽 ~1.27cm）。
  另有：角袋 cut angle 142° / 中袋 104°；角袋 shelf 2.54~5.7cm / 中袋 shelf 0~0.95cm。
- 实测（把源参数与投影换算交叉验证，1m = 854.1px @deviceScaleFactor 2）
  - 角袋 mouth = `cornerGap*√2` = 0.115×1.4142 = **16.3cm** → 比规格**宽 ~40%**（真实角袋是全场最紧的地方）
  - 中袋 mouth = `2*sideGap` = **12.6cm** → ✅ 基本标准
  - 结论：**中袋是对的，角袋偏大**；用户"中袋更大"的感觉来自 3/4 机位（近端中袋最近、
    远端两个角袋被透视压小），并非几何事实。

### 实测手法（可复用）
1. puppeteer 渲染俯视图（隐藏 HUD），用 `new THREE.PerspectiveCamera(42, …)` 复刻机位
   把世界点投影到像素 → 得到 1m = 854.1px 的换算尺；
2. PIL 阈值化找黑区，沿库鼻线扫宽度、沿对角扫进深 → 得到可见开口的 cm 数；
3. 改参数的**预览**不动正式代码：`cp -r` 到 `/tmp/pool_preview/` 再用 python 带 assert 替换，
   渲染出 before/after 对比图给用户看。

### 建议方案（等比缩小角袋，形状完全不变）
`k = 0.115/0.1626 ≈ 0.707`：`cornerGap 0.115→0.0813`、`cornerCapture 0.108→0.0764`、
`pArc 0.098→0.0693`、角袋 `hw 0.078→0.0552`。
预览验证：角袋黑区宽 19.4→13.5cm、进深 75→52mm，黑区面积与中袋基本持平（23894→12830 vs 中袋 13139），
木框/内壁/衬片无破面。等用户拍板后再改正式代码 + 升版号 + 提交。

- AI 不受影响：`plan.power` 直接 `shoot`，不走三角波
- 菜单说明加"力度升满会回落、往返循环"；POOL 暴露 `power` getter + `chargePowerAt`
