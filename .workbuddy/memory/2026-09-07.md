## 砸罐子模式点击失效修复 v3.4.1-vase-click-fix — 已 push `3a94a74`

**用户反馈**：点击主页"砸罐子"卡无任何反应（经典/融合都能进）。

**根因（v3.4.0 两处静默遗漏 + 一个潜在遮挡 bug）**：
1. **`showMenu()` 漏绑 `btn-vase`**：只给 btn-adventure / btn-fusion 设了 onclick，btn-vase 完全没绑 → 点击无反应。
2. **`this.vaseMode` 从未被赋值**：三处代码在"读"它——`startGame:202`（`if (this.vaseMode) setupVases()`）、`WaveManager.update:11`（vaseMode 停刷怪闸门）、`InputManager` 普通点击砸罐分支——但全项目没有任何地方写过 `= true`。vaseMode 永远 undefined(falsy)，即使绑了按钮也进不了砸罐玩法。
3. **潜在遮挡**：`#seed-chooser` 内联 style 同时有 `display:none` 和更靠后的 `display:flex` → 后者生效，选卡黑幕默认可见（平时被 start-menu z-index 2000 盖住）。砸罐开局跳过选卡后这层黑幕会盖住草坪吞掉所有点击。

**修复**：
- 构造函数补 `this.fusionMode = false; this.vaseMode = false;`
- `showMenu()` 绑 `btnVase.onclick`：隐藏菜单 + 隐藏 seed-chooser + `vaseMode=true` + `selectedSeeds=[]` + 直接 `startGame()`（PVZ1 Vasebreaker 规则：无需选卡，植物都在罐子里）；经典/融合按钮补 `vaseMode=false` 重置，防砸罐后回菜单再进其他模式误触发 setupVases
- index.html `#seed-chooser`：删掉前置 `display:none` 与后置 `display:flex` 的重复声明，改为**末尾单一 `display:none`**（flex-direction 等布局属性保留，JS 照常切换 display）

**验证（puppeteer 真实事件）**：`page.click('#btn-vase')` → 菜单隐藏、state=PLAYING、vaseMode=true、罐子 23/26/27（20-28 ✓）、0 pageerror；`page.mouse.click` 罐子屏幕中心 → smashed 1/27 且生成实体。

**教训**：新增模式/大功能提交前必须 grep 该模式标志变量的**赋值点**（`grep -rn "xxxMode" js/`），确认"读的每一处都有写"；提交后应跑一次真实点击的端到端验证（`p.click` 而非 `evaluate` 直调内部函数），否则"内部函数都通、但入口没接"的静默失败会留给用户发现。

## 砸罐子模式（Vasebreaker）v3.4.0-vasebreaker — 已 push `77400fb`

**主页第三张卡**：与"经典冒险"/"融合进化"同款 `.mode-card`（268×292 种子包样式），绿色方框 `.pkt-art` 用 PvZ3 官方 vaseIcon `assets/images/Vase/Vase_Question.png` 作插图。

**规则实现**：
- 三类罐子：植物罐（必出植物）、问号罐（55% 植物 / 45% 僵尸）、僵尸罐（必出僵尸）
- 5×9 棋盘，避开 row0（第一排）与 col0（第一列）
- 罐子数 20–28 随机
- 类型比例：plant 53% / question 27% / zombie 20%（8 trial 验证总和：57% / 20% / 23%）
- WaveManager.update 在 vaseMode 顶部 `return`，所有僵尸来自罐子
- 融合 / 砸罐子模式都关闭随机事件（update / scoreMilestones / triggerRandomEvent 三处 gate 同步加 `|| vaseMode`）
- 胜利判定：所有罐子 smashed + 场上无 `Zombie && !isDead && state!=='DYING'` → VICTORY 横幅 + Final Score + 回主菜单
- 失败沿用原 gameOver（僵尸进房子触发 `x < 40`）

**3 个罐子 sprite 生成**（`assets/images/Vase/*.png`，90×100 RGBA 透明）：
- `Vase_Question.png` = PvZ3 `vaseIcon.png` (220×279 透明) crop alpha bbox + Lanczos 缩到高 86
- `Vase_Plant.png` = 问号罐上 PIL 贴 PvZ1 `SunFlower/0.gif` 头 bbox（32px）
- `Vase_Zombie.png` = 问号罐上 PIL 写白色描边 Arial Bold "Z"（56px）

**关键工程坑**：
1. **PvZ3 vaseIcon alpha bbox 几乎填满 220×279**：原因是 png 抗锯齿边角 + 罐子底部地面阴影都 alpha>0，让 `getbbox()` 返回 (2,2,218,276)。缩放后内容被错误等比拉伸成"飞碟"。改用 `point(lambda v:255 if v>30 else 0)` 取更紧 bbox 后比例正确。**经验：PNG 透明底的 getbbox() 不可信，必须 alpha 阈值收紧**。
2. **权重逻辑错误 1**：原版用 `weights[3 组] 各 1/3 选择 + 组内 pick` → 输出 ~1:1:1（每组内部全 plant/全 zombie/全 question）。必须直接做一个 15 元素的 `drawBag`，按元素数天然加权（8 plant + 4 question + 3 zombie = 53%/27%/20%）。
3. **PvZ3 vaseIcon 与 PVZ1 手绘风差异**：PvZ3 是 3D 渲染，整体作为新模式 sprite 接受，植物头贴 PVZ1 向日葵头形成"罐+叶"风格混搭；用户此前要求"严格 PVZ1 手绘、拒绝 Q 版"，本次砸罐子是新增模式，统一 PvZ3 罐型作风格基线。
4. **Edit 工具"成功"但实际未插入 HTML**：第一次 Edit 用整段 old_string 替换 `</button>\n                </div>`（融合卡结束+menu-cards 结束），报告成功但 grep 不到 `btn-vase`。可能是文件实际缩进与我的 old_string 不完全一致（含不可见字符）。重做时改用更短、更稳的 old_string（仅 `</button>\n                </div>` 前的最后两行）成功。

**fandom / wiki.gg 抓资源**：
- wiki.gg PvZ1 2.PNG 下载成功（实际是 PvZ2 截图，非 sprite）
- PvZ3 Vasebreaker 页面附件：`vaseIcon.png` 220×279 RGBA 透明 OK
- fandom PvZ2 `HD Vase/HD Plant Vase/HD Gargantuar Vase` 在 `&` 后台下载丢失（fandom 限速 / 路径问题）
- 限流策略：wiki.gg 需要带 `User-Agent` header 否则 rate-limit JSON；fandom 单线程串行下载稳但慢
- **结论**：单一 PvZ3 vaseIcon 足够用作问号罐 + 母体，植物罐/僵尸罐用 PIL 程序合成，无需依赖更多外部素材

**puppeteer 验证**：`_verify_vase.js` 三场景：菜单 3 卡 → 选植物+开局 → 砸 6 罐（4 僵尸 2 植物 score=20）→ 强制胜利显示 VICTORY 按钮。无 pageerror。

## 砸罐子 v3.4.3-vase-lantern-rebalance：类型再平衡 + 路灯花揭示 — 已 push `f110299`

**用户需求**（三条）：
1. 植物罐明显少一点、问号罐占多数，加大随机性与策略性
2. 问号罐里出植物时别只给"那几个植物"——可以含一次性植物(樱桃炸弹)及"西瓜"等强力
3. 问号罐出僵尸概率高一点
4. 新增：植物罐小概率含**路灯花**(plantern)，种下后**照亮周围一圈罐子里的内容**

**类型再平衡**：
- drawBag 从 8/4/3(53/27/20) → 5/11/4(25/55/20)，问号成为绝对多数
- 问号罐内部 60% 出僵尸(原 45%)，单关总僵尸 ~12 只(原 ~8)
- 植物奖励池扩充到 27 种：豌豆×3、寒冰×2、双发×2、向日葵、坚果×2、高坚果、樱桃×2、窝瓜×2、火爆辣椒、土豆×2、寒冰菇、大嘴、地刺、三线、裂荚、机枪、西瓜投手、冰西瓜投手、猫尾草
- **问号罐不出 plantern**(防"白白挖坑")；仅植物罐的 27 + 4 plantern 池，约 12.9% 概率出

- 这样 plantern 揭示出来的"小卡预览"**与实际砸出内容完全一致**——揭示是 100% 真相而非概率预告
