## pvz-web v4.0.127 撤销画布缩放上限（用户："调回去，调回去，调回去"）

### 病根
`index.html` 的 `resizeGame()` 被 v4.0.125 写成 `Math.min(scaleX, scaleY, 1.5)`。
**1.5 是"屏幕像素"上限，画布却是 900×600 设计面**：1920×1080 本该 1.8 倍（1620×1080），
被压到 1.5 → 只有 1350×900，四周一圈黑边、整个游戏缩在中间；1512×982 同样被压到 1350×900。
v4.0.125 加上限的动机是「菜单卡片被挤出第一行」——那个问题 v4.0.126 已经用「菜单收口进 900×600 设计面」根治了，
所以上限是纯副作用，必须撤。

### 改动
`const scale = Math.min(scaleX, scaleY, 1.5)` → `const scale = Math.min(scaleX, scaleY)`（index.html resizeGame，约 844~857 行）

### 实测（scale / 画布 / 铺满率）
- 1280×860 → 1.4222 / 1280×853（铺满宽）
- 1512×982 → 1.6367 / 1473×982（铺满高）
- 1600×1000 → 1.6667 / 1500×1000
- 1920×1080 → **1.8000 / 1620×1080**（旧值 1350×900）
- 2560×1440 → 2.4000 / 2160×1440
- 1024×768 → 1.1378 / 1024×683（铺满宽）
画布恒 3:2 不变形。**16:9 屏左右仍会有黑边（1920 下每边 150px）——这是 3:2 画布等比缩放的必然，v4.0.125 之前一直如此，不是本次引入。**

### 验证
`_verify_v4127.js` **11/11**：源码无 `, 1.5` 硬上限 / 每档 scale === min(宽/900, 高/600) / 大屏不再被压到 1.5 /
至少一方向铺满 ≥99.5% / 1920 高度铺满 1080 且宽 1620 / 卡片零越界 / 3:2 不变形 / 零 JS 报错。
回归 4126 15/15、4124 12/12、4123 76/76。截图 `_v4127_menu_1920.png`。

### 教训（重要）
**画布有设计面（900×600）时，任何"上限/下限"都必须换算到设计面坐标再判断**。
写 `, 1.5` 的心智模型是"屏幕别超过 1350 宽"，但代码里它乘的是设计面——
一增一减，用户看到的就是"整体缩小一圈"。以后调 resizeGame 一律先打印 `gameScale` 和画布实际宽高再动手。
